# P2 Prompts

## Prompt 1

Following `skills/prolog-dev/SKILL.md`, start `code/82_q2.pl`.
Implement ONLY the internal predicates to generate and evaluate arithmetic expression trees (`num(N)` and `op(Op, Left, Right)` for `+`, `-`, `*`, `/`) over a non-empty list of non-negative integers in order.
Fuse generation and evaluation (e.g., `build_expr(+Nums, -Tree, -Val)`) so invalid divisions are pruned immediately for speed.
Rules:
- No unary minus, no digit concatenation; negative intermediate values are allowed.
- NEVER use floating-point `/` (it produces floats like `2.0` that break integer arithmetic). For division, strictly require `RightVal =\= 0, 0 =:= LeftVal rem RightVal, Val is LeftVal // RightVal` so all values remain exact integers even when negative.
- Never evaluate by building and parsing strings.
Verify in `swipl` on `[4,2]`, `[8,4,2]`, and a negative-division case.

## Prompt 2

In `code/82_q2.pl`, implement `expr_to_string(+Expr, -Str)` producing an SWI-Prolog string (guaranteed via `format(string(Str), ...)` or `atomics_to_string/2`—NEVER an atom or code list) with no spaces:
- `*` and `/` bind tighter than `+` and `-`; operators are left-associative.
- Left operand parenthesized ONLY if its top op has strictly lower precedence than parent.
- Right operand parenthesized if its top op has SAME or LOWER precedence than parent.
- Single numbers are never parenthesized.
Verify `(4+2)*3`, `4+2*3`, `8/4*2`, `8/(4*2)`, `1-2-3`, `1-(2-3)`, `1+(2+3)`, `1+2+3` and `string(Str)` in `swipl`.

## Prompt 3

In `code/82_q2.pl`, implement `generate_equation(List, Equation)` that splits `List` into two non-empty parts in order, finds equal-value trees `L` and `R` (same exact integer value), and unifies `Equation` with the canonical SWI-Prolog string `"L=R"` (via `format(string(Equation), '~s=~s', [LStr, RStr])`).
Must work whether `Equation` is unbound or ground, and must fail cleanly (no loop, no error) for `[]`, `[X]`, or unsolvable lists. Test in `swipl`.
